## T1 — Task block (track files)

```
### <T><p>.<n> — <title>
Spec: <§x.y, §z, M<p>.<k>>
Covers: <R-<AREA>-<nn>, … or — >
Depends on: <ids or —>
Owns: <paths>
Do:
  - <concrete bullet; exact values copied from the spec>
Tests:
  - <unit|int|e2e|manual: what it asserts>
Done when:
  - <objective, re-runnable check>
```
Follow-ups: `<id>r<k>` (review or gate finding), `<id>a/b` (split). An architect ruling that changes a task is written into its `Do:` as "**Architect ruling <date>:** …".

```

- [ ] <one box per Do bullet>
- [ ] Test: <one box per Tests item>
- [ ] Done: <one box per Done-when condition>
```
Ticks keep a note after ` — `: `- [x] Done: … — Gate P3: 16/16 nodes one version`.

## T3 — Universal per-task checklist

Full text for the project's `checklists/00-universal-task-checklist.md` (every task carries it: in the PR body in per-task-PR mode, in the final report otherwise):

```markdown
# Universal per-task checklist
## Before coding
- [ ] Read every spec section the task cites, in full, this session
- [ ] Read the contract sections the task touches; no DTO invented
- [ ] `Depends on:` tasks are merged on the integration tip I synced to (<sha>)
- [ ] Duplicate check done (08 §4): no other branch holds commits for my ids
- [ ] The phase is open and my track has this task in this batch
## While coding
- [ ] Every `Do:` bullet is in the diff; nothing more
- [ ] Only files in `Owns:`; cross-track needs listed in the report, not edited
- [ ] Every boundary validated with a schema; types inferred, not duplicated
- [ ] No placeholders, TODOs, suppressions, skipped tests, mock in a live path
- [ ] No paid call, no real key, no secret in code/tests/fixtures/logs
- [ ] Files stay under ~300 lines; split before adding
- [ ] Logs structured with the ids a human needs; errors classified with contract codes
- [ ] New env vars / endpoints documented where the project documents them
- [ ] (UI) loading, empty, error, success states; both themes; keyboard; min width
## Verification
- [ ] Every `Tests:` item exists, names its requirement id, and one fails without my change
- [ ] `check` green; the track suite green; expensive tests only in their project
- [ ] Every `Done when:` reproduced with the command and result in the commit/report
## Docs
- [ ] PROGRESS line; DECISIONS line for any choice made; BLOCKERS for anything stuck
- [ ] Track checklist boxes ticked in the same commit, notes after ` — ` on open ones
- [ ] Commit `<task-id>: …` with the required trailers; contract change called out
```
